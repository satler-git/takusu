# 音声アシスタント

takusu の「音声アシスタント」は、マイク入力を受け取り、**STT（Speech-to-Text、音声認識）**でテキスト化します。
LLM で意図を解釈してタスクとスケジュールの操作を行い、**TTS（Text-to-Speech、音声合成）**で応答します。

## STT（音声認識）

「STT」では、主に **Sherpa-ONNX** ローカル推論を使います。

- 録音：マイク入力を取得し、WAV 形式で処理する。
- フォーマット：`f32` または `i16` のモノラル、16kHz リサンプリング。
- モデル：`sherpa-sense-voice-int8`（初回自動ダウンロード）。
- 言語：`auto`、`ja`、`en`、`zh`、`ko` など。

録音からテキスト化まではモバイルアプリ内で行い、テキスト化された内容のみをサーバーに送信します。

## TTS（音声合成）

「TTS」では、以下のバックエンドを使えます。

- **Cartesia Sonic**：クラウド TTS で、高品質かつ多言語に対応する。
- **Android TTS**：モバイルアプリ内蔵の TextToSpeech エンジン。

`takusu-audio` クレートは `TextToSpeech` トレイトを定義しており、新しいバックエンドを追加できます。

## Resident Agent

モバイルアプリでは、常駐型の **Resident Agent Button** をホーム画面に表示しています。

- タップ：Agent 画面（`/agent`）を開く。
- 上スライド：タスク追加画面（`/task/add`）を開く。
- 長押しによる音声入力は **未実装** です。

処理中と読み上げ中はアイコンとアニメーションで状態を表示します。

## 承認フロー

タスクの作成、更新、削除などの永続的な変更は、LLM が提案した後にユーザーが承認するまで確定しません。
これにより、音声入力の誤認識による意図しない変更を防ぎます。

## 連続音声セッション

ユーザーが明示的に開始する間は、以下を繰り返します。

```text
録音 → 認識 → 思考/ツール実行 → 応答（テキスト、TTS）
```

**VAD（Voice Activity Detection、音声区間検出）** による自動発話区間検出と、**barge-in**（TTS 中のユーザ発話による割り込み）は **未実装** です。
録音の開始と終了はユーザーが手動で行います。

## プライバシー

- 常時リスニングは行わない。
- マイク使用中はユーザーに通知を表示する。
- 対象外の音声は外部送信と永続化を行わない。
- raw audio、transcript、機密情報をログに記録しない。
